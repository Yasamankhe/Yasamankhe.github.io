Robotic Piano Actuation System

I worked on the actuation hardware for a robotic piano system that could physically press keys using custom-built solenoids. My work focused on the solenoid and hand geometry, CAD iteration, and a Python positioning script that mapped all 54 keys to motor tick positions for reliable movement on the real system.

SolidWorks Python Electromechanical Design System Integration FDM Printing Robotics

Project Overview

The goal of this project was to build a mechanism that could press piano keys using custom actuators instead of hand-played motion. I worked on the hand-side actuation concept, including the solenoid hardware, structural layout, and positioning logic needed to move to the correct key.

The custom solenoid was manufactured to match the dimensions required by the hand base. After the housing and plunger were built, the coil was wound to fit inside the enclosure while still producing enough actuation force. In testing, the solenoid operated at 12 V with a current draw of about 600 mA, corresponding to a resistance of roughly 20 ohms. That aligned well with the electronics used by the circuit team and made integration easier.

The Approach and Process

I designed the finger and joint structure so the mechanism could press both natural and sharp keys. That let the hand move flexibly instead of being restricted to a single octave position. I also used fixed mounting holes and repeatable geometry to keep the mechanism aligned as the assembly evolved.

One of the main design challenges was reducing the air gap so the force from the solenoid would transfer more effectively into the finger. To improve that, I iterated the joint structure and printed multiple versions in 1 mm increments so I could test different lengths and adjust quickly.

Material choices mattered here too.

The solenoid housing used mild steel because it provided a good magnetic path and did not permanently magnetize easily. The plunger was also made from mild steel, while the guide rod used stainless steel because magnetic permeability was not important there.

Key Positioning Mapping Script

A key part of this project was making sure the actuator moved to the exact position of each key. I wrote a Python script that calculated the motor tick positions for all 54 keys based on keyboard geometry, key width, octave spacing, rack pitch, and gear tooth count.

I also included an adjustable offset so the model could be calibrated against the actual assembled hardware. That made the script useful not just in theory, but during real system integration. 

import math

PITCH = 2.0
TEETH = 39
MM_REV = TEETH * PITCH
MILLIRAD_REV = 2.0 * math.pi * 1000.0
TICKS_PER_MM = MILLIRAD_REV / MM_REV

OFFSET_TICKS = 0   # Measured after final hardware assembly
NATURAL = 22.25    # Width of one natural key (mm)
OCTAVE = 7 * NATURAL

CENTER = {
    'C':  0.50, 'C#': 0.95, 'D':  1.50, 'D#': 2.05, 'E':  2.50,
    'F':  3.50, 'F#': 3.93, 'G':  4.50, 'G#': 5.00, 'A':  5.50,
    'A#': 6.07, 'B':  6.50,
}

NOTES = ['C', 'C#', 'D', 'D#', 'E', 'F', 'F#', 'G', 'G#', 'A', 'A#', 'B']
NUM_KEYS = 54

keys = []

for i in range(NUM_KEYS):
    oct_idx = i // 12
    note = NOTES[i % 12]
    mm = oct_idx * OCTAVE + CENTER[note] * NATURAL
    keys.append(mm)

for i, mm in enumerate(keys):
    ticks = round(mm * TICKS_PER_MM + OFFSET_TICKS)
    comma = "," if i < NUM_KEYS - 1 else ""
    print(f"    {ticks:<8}{comma} [{i}]")
