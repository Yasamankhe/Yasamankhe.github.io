Simple RISC Machine

I designed a 16-bit multi-cycle processor in SystemVerilog. I built the register file, ALU, shifter, datapath, instruction decoding logic, and finite state machine controller, then wrote RTL testbenches to exercise the individual blocks and end-to-end instruction execution.

16-bit datapath
8 × 16-bit registers
4 ALU operations
4 shift modes
N / V / Z status flags
Multi-cycle FSM control
01

Architecture

I separated the processor into a controller and a datapath. The controller decodes the current instruction and generates the control signals that determine which registers are read, when intermediate values are loaded, which ALU operation is performed, and when a result is written back.

The datapath contains the register file, operand registers, shifter, ALU, result register, status logic, and the multiplexers used to select operands and writeback data.

02

Instruction Decoding

The CPU stores the incoming 16-bit instruction in an instruction register. I then split the instruction into the opcode, ALU operation, register fields, and shift control field.

Opcode
Bits [15:13] select the main instruction class.
Operation
Bits [12:11] select the operation inside that instruction class and are also used as the ALU operation control.
Rn
Bits [10:8] select the first source register or the destination register for an immediate move.
Rd
Bits [7:5] select the destination register for ALU results.
Shift
Bits [4:3] control the shifter applied to the Rm operand.
Rm
Bits [2:0] select the second source register.
Immediate
For immediate moves, I sign-extend the lower eight instruction bits to the full 16-bit datapath width.
03

Register File

I built an eight-entry register file with sixteen bits per register. The register file has one read port and one write port.

Reads are combinational, so changing the readnum input selects a new register value without waiting for a clock edge. Writes are synchronous and only occur on a rising clock edge when the write control signal is asserted.

Registers
R0 through R7, each 16 bits wide.
Read
A combinational multiplexer selects one of the eight registers using the 3-bit readnum input.
Write
On the rising clock edge, the value on data_in is written to the register selected by writenum when write is enabled.
Register Selection
Inside the CPU I use the nsel control to choose whether the datapath accesses Rm, Rd, or Rn.

05

Status Flags

The ALU also produces zero, negative, and overflow information from the current result.

Z | Zero
Z is asserted when the 16-bit ALU output is zero.
N | Negative
N follows the most-significant bit of the result, so it indicates a negative two's-complement value.
V | Overflow
I detect signed overflow separately for addition and subtraction by comparing the operand and result sign bits.
06

Instruction Execution

My CPU testbench exercises immediate moves, arithmetic, logic, shifted operands, and comparison behavior across the complete CPU and datapath.

Instruction Operation What I Tested
MOV Rn, #imm8 Sign-extended 8-bit immediate is written directly into Rn. I tested immediate writes to multiple registers.
ADD Rd, Rn, Rm Adds Rn to the optionally shifted Rm operand and writes the result to Rd. The CPU testbench includes ADD using an LSL-shifted second operand.
AND Rd, Rn, Rm Performs a bitwise AND and writes the result to Rd. I checked the resulting destination register value.
MVN Rd, Rm Inverts the optionally shifted Rm operand and writes the result to Rd. I tested both unshifted MVN and MVN with LSL #1.
CMP Rn, Rm Subtracts the second operand for comparison and exposes status information rather than writing a general register result. I tested both a negative comparison result and a zero comparison result.

Why multi-cycle control?

Breaking instruction execution into states lets the same datapath hardware be reused across different parts of an instruction. Registers can be read in one state, the ALU used in another, and the result written back on a later clock cycle.

08

RTL Verification

I wrote separate SystemVerilog testbenches for the main building blocks and a CPU-level testbench that drives complete encoded instructions through the processor.

MODULE TEST

ALU

I test addition, subtraction, bitwise AND, bitwise NOT, multiple operand combinations, and zero-result detection.

MODULE TEST

Register File

I write values into R0 through R7 and read them back to check register addressing and synchronous write behavior.

MODULE TEST

Shifter

I exercise pass-through, logical shift left, logical shift right, and arithmetic shift right with several 16-bit patterns.

SYSTEM TEST

CPU

I load complete 16-bit instructions, start the controller, wait for execution to complete, then inspect destination registers and status outputs.

MOV Immediate
The CPU-level testbench writes several immediate values into different registers and checks the register contents.
Shifted ADD
One test performs an ADD using a left-shifted register operand and checks the final destination value.
Logic
AND and MVN are tested by comparing the actual destination registers against the expected bitwise results.
Shifted MVN
I also test MVN after applying a logical left shift to the source operand.
CMP Flags
The CPU testbench checks a negative comparison and a zero comparison using the N and Z outputs.
09

Implementation Details

I kept the main hardware blocks separate so I could test them independently and then instantiate them inside the datapath and CPU.

cpu.sv
Instruction register, instruction decoding, register selection, sign extension, control FSM, datapath control, and top-level CPU integration.
datapath.sv
Connects the register file, operand storage, shifter, ALU, result register, operand multiplexers, writeback selection, and status outputs.
ALU.sv
Combinational arithmetic and logic block with ADD, SUB, AND, NOT, and N/V/Z generation.
regfile.sv
Eight 16-bit registers with one combinational read port and one synchronous write port.
shifter.sv
Combinational operand shifter supporting no shift, LSL #1, LSR #1, and ASR #1.
Testbenches
Separate RTL tests for the ALU, register file, shifter, and complete CPU behavior.
