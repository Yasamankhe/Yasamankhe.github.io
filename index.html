Simple RISC Machine

I designed a 16-bit multi-cycle processor in SystemVerilog. I built the register file, ALU, operand shifter, datapath, instruction decoding logic, finite state machine controller, and status-flag logic, then wrote RTL testbenches to exercise the individual blocks and end-to-end instruction execution.

Simple RISC Machine

01

Architecture

I separated the processor into a datapath and a multi-cycle controller. The controller decodes the instruction fields and generates the control signals required to move operands through the datapath over multiple clock cycles.

The datapath contains the register file, operand registers, shifter, ALU, result register, status logic, and the multiplexers that select register addresses, immediates, and write-back data.

opcode, op, Rn, Rd, shift, Rm, immediates

Control

Multi-Cycle FSM

Instructions progress through a sequence of states rather than performing every operation in one clock cycle.

Datapath

16-Bit Data Path

Operands, ALU results, immediates, and register values are represented as 16-bit values.

Storage

Eight General Registers

The register file provides eight 16-bit registers with combinational read and synchronous write behavior.

Status

N / V / Z Flags

The processor tracks negative, overflow, and zero conditions for comparison and arithmetic operations.

03

Register File

I implemented an eight-entry, 16-bit register file. Register values can be read combinationally while writes occur synchronously on the active clock edge.

The controller uses the register-select logic to choose between the Rm, Rd, and Rn instruction fields depending on which operand is needed at that point in the instruction sequence.

Capacity

8 × 16 Bits

Eight general-purpose storage locations, each holding one 16-bit value.

Write

Synchronous Update

Register writes occur on a clock edge when the controller asserts the write enable.

04

ALU & Shifter

The datapath includes a 16-bit ALU and a separate operand shifter. This lets an operand be shifted before it reaches the ALU, so shift behavior can be combined with arithmetic or logic instructions.

05

Status Flags

The ALU datapath generates three status conditions used during arithmetic and comparison behavior.

Z

Zero

Asserted when the ALU result is zero.

N

Negative

Derived from the most significant bit of the signed result.

V

Overflow

Detects signed overflow during addition and subtraction.

CMP Subtraction-based comparison and N/V/Z flag updates.
07

Multi-Cycle Control

The controller sequences instructions through several states so register reads, operand loading, ALU execution, write-back, and flag updates occur at the correct time.

ADD / AND / MVN: Wait → Decode → GetB → ALUOp → WriteReg → Wait
CMP: Wait → Decode → GetB → ALUOp → UpdateFlags → Wait
MOV immediate: Wait → WriteImm → Wait
